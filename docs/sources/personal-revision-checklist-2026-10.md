## 1. 术语表修正：翻译腔术语不算学术词（`references/terminology-and-register.md`）

现有表把"闸 → 检查关卡"列为可选学术表达，并把"契约"列为可保留的已定义术语。作者在后续改稿中否决了这两个词，理由是它们是英文（gate、contract）的直译，本领域（智能体 / 工作流 / CFD）的中文文献里没人这么说，读者会感到突兀。请改为：

| 原表达 | 曾用改法（废弃） | 现采用 | 判断要点 |
|---|---|---|---|
| 闸 / 检查关卡 | 检查关卡 | 阶段校验、检查点 | "关卡"仍口语 |

| 门槛 | — | 验收阈值、阈值 | |
| 熟悉的（通用做法） | — | 训练数据中常见的（通用做法） | 不用拟人词描述模型，写成机制 |

新增一条通用规则：**英文术语直译检查**。遇到由英文概念译来的名词（contract、gate、outcome、probe、pipeline 等），先查目标领域中文文献的通行译法；若要保留某个直译，须能给出同一领域（不是别的学科）文献使用该译法的引用，否则换成领域通行词或直接描述其作用。"捷径""指纹"等正文已正式定义且作者有意保留的词不受此条影响，但应在作者侧记录保留理由，避免后续被误改。

## 2. 摘要写作结构（新文件 `references/abstract.md`，并在 SKILL.md"按任务读取"加入口）

作者给的样板逻辑来自 XFluids 论文的摘要（Computer Physics Communications）。规则：

1. **顺序固定**：问题用外行能读懂的话说清 → 做了什么 → 关键定量结果（两到三个数） → 末句明确定位"与××相比，本文……"，直接点出创新点。
2. **少用需要解释的专业词**：摘要里凡是需要定义、需要引用才能理解的词都换成描述；术语留给正文首次定义。不含公式与变量符号。
3. **末句不写"本文具有重要意义"一类评价**，写比较对象和区别本身。
4. 中英文摘要逐句对应；字数按期刊要求（本次中文 298 字、英文 150 词）。

可用本次定稿作为示例（见本文件末尾附录 A）。

## 3. 引言收尾：先把问题成因讲清，再引出本文（`references/argument-and-voice.md`"建立读者能跟随的论证"）

作者要求：引言最后一段引出本文工作之前，不能只说"存在××问题"，要把**问题为什么发生**讲成一个读者能跟上的机制链。本次的链条是：大模型知识来自训练数据 → 训练数据截止于发布前（举 GPT-4 技术报告：2021-09 截止、2023-03 发布）→ 新发表的格式不在训练数据中，而相近的经典格式大量出现 → 遇到欠定细节时模型用记忆里的相似格式补全 → 这种替代也能通过数值检查 → 因此需要以忠实为首要目标并审查方法结构。

规则表述建议："引出本文工作的段落应包含：问题的触发条件、产生机制、为什么现有检查发现不了、本文因此选择的切入点。每个环节至少一句，有证据的环节给引用。"

## 5. 方法 / 工作流类论文要有直接的结果图（`references/argument-and-voice.md`"结构编辑的范围"）

作者反馈：只有收敛阶表和误差曲线，复现"成功"的说服力不够，要求补算例结果图（解的剖面 / 云图）。规则：

- 凡声称"复现了某方法"的论文，正文至少有一幅直接展示解的图（间断算例剖面、流场云图等），不只有收敛曲线。
- 配图段落固定写四件事：算例设置（计算域、初值、终止时间、CFL、边界、网格数）；参考解是什么以及它的性质（同格式加密 vs 独立低阶格式）；比较了哪些可量化特征（激波位置、特征位置差、振幅比、正性）；与原论文设置的差异用一个从句说明（如"论文未给出该算例的网格数"）。
- 不写"数据来自已有运行、未重新计算"之类自证句；数据路径、commit、summary 字段名放作者侧记录。
- 参考解是低阶格式时，峰值差异的方向要解释为参考解的耗散，不能写成复现误差，也不能回避。

## 附录 A：本次定稿摘要（供 `references/examples.md` 收录）

> 本文提出一种引导编程智能体依据论文忠实复现高阶数值格式的工作流。编程智能体已能编写求解器代码，但其大模型知识截止于发布之前，面对新发表的格式，常以记忆中相似的格式代替，而替代程序仍能通过精度检验。为此，工作流将复现分为从格式抽取到逐项对比的5个阶段，并建立检查代码结构的判别方法。映射WENO格式的复现误差与原文表值逐行一致；紧致全离散WENO格式的50次重复实验全部通过精度检验，结构检查仅确认5次忠实复现、13次替代；改进后的流程将忠实复现率由20%提高至100%。与现有用于配置既有求解器的计算流体力学智能体相比，本文工作使智能体能够在求解器中新增论文提出的格式，并检验其是否采用论文方法。
