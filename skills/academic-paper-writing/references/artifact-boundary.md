# 正文与材料边界

这一整合规则对应用户关于论文与复现文档分工的要求，并参考 scholar-papercraft 对内部溯源与成稿分离的设计。上游文件保持在独立仓库，此处按本项目需求独立表述。

## 按读者需要分配内容

| 内容 | 通常的位置 |
|---|---|
| 研究问题、方法机制、研究设计、关键实验条件、主要结果和解释 | 正文 |
| 主张成立所需的假设、统计不确定性、影响核心结论的失败结果 | 正文中的相关位置 |
| 完整推导、扩展实验、较长参数表、次要分析 | 附录或补充材料，正文保留必要引用 |
| 公开代码仓库、数据 DOI、正式数据或代码可用性声明 | 期刊规定的声明位置，必要时正文引用 |
| 安装命令、环境文件、运行顺序、目录说明、SHA 和校验步骤 | 公开复现仓库的 README 或专门复现文档 |
| 结果到原始文件的对应、运行日志、核验状态、agent 工作记录 | 作者内部记录 |

这是用途判断，不是绝对文件名禁令。若研究对象本来就是文件格式、哈希算法、代码接口，或期刊明确要求某标识，正文可保留必要标识。软件名、版本、公开数据集编号和研究中实际使用的算法名也可能不可省略。

## 从实验材料到科学描述

从结果文件中提取条件、变量、样本数、统计量、比较基线与结果。正文以这些科学事实及其图表为支撑，不以“CSV 的第几行已核验”作为论证。路径对应关系继续存在于作者侧记录中。

删除“数据真实”“非合成”“已经核验”等自我认证措辞前先辨别其作用：

- “来自实际临床采集，而非模拟”可能是必要研究设计信息，应在方法中准确说明。
- “请放心，本表每个结果都来自真实运行”通常只是工作汇报。
- “每份样本独立测量三次”是实际实验方案，不能当成自证语句删掉。

若一句话包含科学事实和文件定位，仅移出定位信息。不要删除整句，不要把“来自该文件”改成没有依据的“经过独立验证”。

“未重新运行模型”若仅描述这次改稿的操作，移出正文；若研究本身是既有运行记录的回顾性分析，则在方法中保留准确的数据获取方式，不能改写得像进行了新的实验。

## 写作与投稿元信息

删除成稿中“本文基于已有论文与日志撰写”“作者信息投稿前补齐”“正式投稿前补充链接”等工作过程或待办句。缺失信息在作者待办、LaTeX 注释或 Word 批注中标记；仅在明确的草稿交付中使用可见占位符，并说明未完成项。最终正文和编译后的论文不能残留占位符。

代码与数据可用性可简洁说明实际发布状态和真实地址。尚未发布时不写“已开源”。一个开源声明通常足以承载获取方式，但不能替代期刊规定的声明或方法中的科学信息。

## 迁移不等于丢弃

对要移出的有效复现信息，在作者侧记录“原位置、信息、建议去向、是否已迁移”。只有实际修改目标文件后才标记已迁移。没有仓库地址时，不编造链接；缺失的发布信息作为作者问题处理。

正文必须仍能让读者理解并评估研究。不能用一句“详见 GitHub”替代关键设计、排除标准、统计分析或影响结论的条件。
