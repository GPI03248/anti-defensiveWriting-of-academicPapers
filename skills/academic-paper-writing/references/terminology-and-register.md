# 术语与中文表达

来自项目创建者的《学术论文修改要点（个人复用清单）》；该清单由作者此前改稿 PROMPT 经 Claude 整理。这里将个人实践转化为可迁移规则。

## 领域习惯与全文一致性

优先使用目标读者普遍熟悉、含义明确的术语形式，不为“中文规范化”而强译。token、agent、benchmark 等在目标领域通行时，可以首次附中文解释，后续统一形式；若期刊要求中文或双语，则遵照要求。不要由一个改稿案例推断某英文形式在所有领域都优于中文。

已经定义的名称、缩写、分类和术语保持一致。新增或修改名称时检查正文、图表及中英文摘要。正式定义的“捷径”“指纹”“契约”等可保留，但首次定义要清楚，不随意改成不同概念。

## 识别口语、借喻和领域撞词

下表用于提示上下文判断，不是自动替换字典。

| 原表达 | 按实际含义可选的学术表达 | 判断要点 |
|---|---|---|
| 承重结构 | 可靠性保障、关键结构要件 | 力学论文中的真实承重结构是专业内容，保留 |
| 闸、地板 | 检查关卡、阈值、下限 | 区分流程检查、数值下界与实际物理对象 |
| 兜底、过测、跑通 | 补救、通过测试、正常运行或完成 | 不能把“能运行”改成“通过全部验证” |
| 喂答案、红线 | 提供答案、基本约束 | 根据真实动作和约束内容选择 |
| 挑、停在、补齐 | 选择、中止于、补充完善 | 保持动作和完成状态 |
| 空壳 | 接口桩 | 只有确指未实现功能的接口时才使用此名称 |
| 探针 | 运行检测 | CFD 中真实的流场测点仍称探针 |
| 靶标 | 复现对象 | 根据上下文；实际靶标不改 |

“下面不按时间罗列，只讲……”可直接说明实际组织方式，如“以下按问题类型归纳……”。版本提交数与迭代轮数等统计口径应准确解释一次；如果迭代未被记录会影响统计解释，保留这一事实。

“值得注意的是”没有增添含义时可删；“一次也没有出现”“无一例外”应改为准确的观测描述，不能删掉确实为零的结果或改变计数。不要仅因措辞绝对就弱化有证据的陈述。

中文期刊要求客观叙述时可用“本文”或具体方法作主语；“我们认为”不机械全篇替换为“本文认为”。英文论文中的 we、作者已有语体和期刊允许的表达按实际规范处理。摘要的主语要求见 [期刊适配](venue-adaptation.md)。
